# RayNeo Workspace 正式项目交接

交接日期：2026 年 10 月 10 日。当前基线：v0.8。项目目标是在 M2 MacBook Air 上，通过 USB-C 直连雷鸟 GT，在眼镜中使用三个独立 macOS 桌面，并保持原生鼠标、键盘和窗口拖拽操作。

用户已确认 v0.8 的三屏显示和原生跨屏操作可用，反馈为“完美”。后续应先把这份可用原型迁入独立项目，保留可回退基线，再逐项完善工程结构、签名、性能和稳定性。

## 用户需求和已确定的产品方向

用户设备是 M2 MacBook Air 和雷鸟 GT，希望构建用于编码、文档、终端的空间工作环境。当前方案运行在 macOS 上，不需要 DisplayLink 扩展坞，不刷固件。此前提到的 Omarchy 是备选方向，当前交付没有实现 Linux 支持。

三个桌面必须是能放置真实应用窗口的独立系统显示器。鼠标必须像普通外接显示器一样自然跨屏，不应要求切换眼镜鼠标模式，也不应依靠快捷键完成正常操作。窗口移动快捷键可以作为可选便利功能。

## 实现结构

```text
RayNeo GT HID → GTTracker → yaw → SceneKit 相机

CGVirtualDisplay × 3
        ↓
ScreenCaptureKit × 3 → CVPixelBuffer → CIImage → CGImage
        ↓
SceneKit 三个平面 → GT 实体显示器上的无边框窗口

鼠标和键盘 → macOS 原生扩展桌面 → 真实应用窗口
```

`GTTracker` 使用原生 IOKit HID 接口接收陀螺仪数据。启动时估计约两秒静止零偏，减去零偏后积分角速度。当前时间步长来自主机单调时钟，并限制最大值为 0.02 秒；传感器轴、方向、暂停和回中保留在原型中。

`DesktopCapture` 为三个虚拟显示器分别建立捕获流。只处理完整有效帧，经 Core Image 转成 `CGImage`，在主线程更新 SceneKit 材质。原生光标包含在捕获中，不捕获音频。

`DemoDelegate` 管理创建桌面、会话布局、测试窗口、捕获启动、GT 输出窗口和退出清理。使用 `generation` 标记防止取消启动后的异步回调继续写入旧状态。

`WindowShortcuts` 只注册可选的全局窗口移动快捷键，未接管鼠标，也未记录键盘内容。窗口移动通过辅助功能接口修改选中应用窗口的位置，必要时缩小以适应目标屏幕；全屏窗口会提示先退出全屏。

当前三个平面以约 −48、0、+48 度排列，距离为 3，宽度 2.50，宽高比 16:9，相机水平视场约 46 度。缩放范围为 65% 到 125%。这些是原型参数，应先保存基线再改。

## 原生输入的关键设计

会话中的排列顺序是：

```text
Mac → RayNeo Left → RayNeo Center → RayNeo Right → GT 实体输出屏
```

GT 实体屏只显示空间合成场景；三个虚拟屏才是放真实应用窗口的工作桌面。把 GT 输出屏放在工作桌面之后，避免它夹在 Mac 和虚拟屏之间，阻断拖拽路径。

GT 输出窗口覆盖该屏幕的菜单栏，忽略鼠标事件，并在系统屏幕参数变化时重新定位。普通输入不经过任何自定义事件转发。v0.8 已彻底删除鼠标事件 tap、鼠标重发、鼠标位置强制移动、黄点覆盖层、速度缩放和模式切换。

停止时尝试恢复 GT 原会话位置，释放虚拟桌面，停止捕获，关闭测试窗口。退出时再关闭 IMU 流。当前捕获停止部分采用异步任务；异常退出与清理顺序是后续应重点审计的地方，不能假定强制退出也能执行正常清理。

不要重新引入已经失败的“空间鼠标模式”。用户明确不接受为了办公反复切换鼠标模式或必须依靠快捷键操作。

## GT 协议和设备探测

当前设备信息：VID `0x3941`，PID `0xAF50`，HID usage page `0xFF00`，usage `0x01`，本次 USB 接口为 0。不要直接照搬其他设备或旧固件的 interface 5 假设。

输入和输出报告均为 64 字节。被动监听最初收不到 IMU 报告，需要开启运行时 IMU 流。

| 操作 | 64 字节输出报告 |
| --- | --- |
| IMU 开启 | 开头 `66 01 00`，其余填零 |
| IMU 关闭 | 开头 `66 02 00`，其余填零 |

输入包以 `99 65` 开头；陀螺仪 X、Y、Z 是偏移 16、20、24 的 little-endian Float32，单位为度每秒。本次 12 秒诊断获得 5584 个有效样本，约 465 Hz。协议参考中加速度位于偏移 4、8、12，温度位于 28，tick 位于 40；当前正式基线主要读取陀螺仪字段。

现有程序只允许上述运行时开关指令，不包含固件刷写、永久校准写入或任意设备命令。GT 应使用“跟随模式”，避免眼镜内部固定模式与软件姿态追踪叠加。

## 构建和运行

需要 macOS SDK 和 Swift 编译器。当前是单文件 Swift 编译，不依赖 Swift Package Manager 包或第三方驱动。构建脚本未显式设定最低系统版本，当前工具链默认 target 为 arm64 macOS 26.0；正式分发前应明确部署版本并实机验证，不能假定当前二进制支持旧系统。

在正式项目目录内执行：

```sh
bash build.sh
open build/RayNeoWorkspace.app
```

构建脚本显式传入 SDK 和 Objective-C bridge header，生成：

```text
build/WorkspaceDemo
build/RayNeoWorkspace.app
```

应用 bundle identifier 当前为 `local.rayneo.workspace.demo`，版本为 `0.8`。迁移阶段先保留，避免把应用迁移、签名变化和业务改动混在一起。后续正式命名应明确处理用户授权迁移。

拆分 Swift 文件时注意：目前最末尾有顶层应用启动代码。采用多文件编译后，应放到 `main.swift`，或改成适合目标工程的应用入口。不要仅拆文件后保留任意文件内的顶层入口。

## 权限和签名

屏幕录制权限是三屏捕获必需的。普通跨屏鼠标和键盘不需要辅助功能权限；可选窗口移动按钮和 `⌘⌥1/2/3/0` 需要辅助功能权限。

应用目前使用 ad hoc 临时签名，尚未 Developer ID 签名或公证。此前 rebuild 后出现“系统开关已开启，但程序仍提示无权限”的原因，经 `tccd` 日志确认是旧代码要求与新代码哈希不匹配，而不是用户漏点授权。

若确认为签名变更造成的屏幕录制授权失效，可针对该应用执行：

```sh
tccutil reset ScreenCapture local.rayneo.workspace.demo
```

只有辅助功能也因签名变化失效时，再针对该应用重置：

```sh
tccutil reset Accessibility local.rayneo.workspace.demo
```

然后由用户在系统设置重新授权，按系统要求退出并打开。不要重置所有应用的权限，不要在用户刚授权后再次编译签名同一应用。开发工作流应优先改用稳定签名身份；安装证书、使用付费开发者账号和公证需要根据正式项目的实际配置处理。

此前 Codex 执行沙箱内的 HID 和显示器枚举结果不可靠，沙箱外运行才识别到实际设备。诊断时应区分执行环境限制和程序自身错误。不能为了绕过开发沙箱限制，直接把产品设计改成默认需要 root。

## 使用和诊断

日常操作从 Mac 控制面板开始：启动三屏、回中、放大缩小、停止、退出。控制面板关闭后可从菜单栏“GT 三屏”重新打开。

可选窗口移动：先选中应用窗口，按 `⌘⌥1`、`⌘⌥2`、`⌘⌥3` 送到左中右屏，`⌘⌥0` 送回 Mac。按键只是便利方式，原生拖拽是主要操作。

原型的 R、C、F、X/Y/Z、空格、H、加减和 Esc 等场景按键依赖窗口焦点，不应写成随时可用的全局操作。此前用户反馈过 Esc 无效；退出应继续保留控制面板和菜单入口。

程序每秒将状态写入应用包同目录的 `runtime-status.json`，通常是 `build/runtime-status.json`。当前包含状态、IMU 样本数、虚拟显示器 ID、捕获帧数、`inputMode: native` 和虚拟屏坐标。该文件无屏幕图像，但正式应用应改用合适的用户数据或日志目录，避免安装目录不可写。

当前没有保存视频、音频或网络上传代码。静态桌面的完整捕获帧数可能低于 30 帧每秒，不应仅凭该计数断定掉帧。性能验收应使用可重复的动态内容并测量 CPU、GPU、内存、功耗及延迟。

## 正式项目迁移步骤

1. 复制 `Sources/`、`build.sh`、`.gitignore`、`README.md`、`DEVELOPMENT_NOTES.md`、`HANDOFF.md` 和探针源码到独立目录。发布包另行保留。不要迁入旧实验二进制或运行日志。
2. 在新目录初始化独立 Git 仓库，保存 v0.8 基线提交与标签。当前交接没有创建独立仓库、推送远程或建立 Codex 新聊天。
3. 先做一次无功能改动构建。注意签名和权限变化；确认三屏、GT 跟随模式、原生输入和退出清理仍然可用。
4. 确定工程形式。可以先保留脚本编译，再建立 Xcode 工程并拆分设备通信、虚拟屏、捕获、渲染、窗口管理和控制界面。
5. 每次只改变一个方向。保留当前可用 app，实验版使用独立产物路径；不要让实验构建反复覆盖用户正在使用的应用。

## 优化顺序和验收

| 优先级 | 工作 | 验收重点 |
| --- | --- | --- |
| 第一批 | 固定开发签名，明确版本和发布流程 | 同一身份下更新后授权行为稳定，能回退到 v0.8 |
| 第一批 | 拔插、睡眠唤醒和退出清理 | 不遗留虚拟屏，恢复 GT 布局，捕获和 IMU 可重新启动 |
| 第二批 | 拆分工程，保存设置和工作区 | 保留原生输入；重启后恢复用户选择的大小和间距 |
| 第二批 | 优化视频纹理路径 | 对比当前逐帧 `CGImage` 转换，测量功耗和延迟后再改用 GPU 纹理 |
| 第三批 | 姿态融合和长时间漂移 | 测量静止与转头误差；改进零偏和回中；不要宣称仅靠陀螺仪能消除绝对 yaw 漂移 |
| 第三批 | 清晰度和布局 | 可调距离、间距、曲率；真实代码和文档长期阅读测试 |

测试优先覆盖设备包解析、状态取消、布局保存恢复和生命周期等容易回归的逻辑。图形输出、跨屏拖拽、真实权限、热拔插和长时间体验需要在设备上验证。当前没有自动化测试套件，不要把编译通过当成这些功能都已验证。
