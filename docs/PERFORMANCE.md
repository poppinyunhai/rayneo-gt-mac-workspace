# 性能、阅读与漂移验收

本轮已提供比较工具，没有将合成测试结果描述为眼镜端功耗/延迟收益。所有实机数据在统一验收时采集。

## 可重复动态负载

1. 启动三屏，关闭不相关的大负载应用，保持 GT 连接方式、电脑供电方式和屏幕大小相同。
2. 选择均衡 30/60 fps 与 Core Image 兼容模式，停止再启动以应用设置。
3. 点击“性能测试”，三屏各出现滚动代码与移动色块。等待 15 秒稳定。
4. 执行 `python3 scripts/collect-metrics.py --duration 60 --output build/compat-balanced.csv`。
5. 停止动态测试与三屏，切换 Metal，重新启动、等待同样时间，再采集 `build/metal-balanced.csv`。
6. 同样比较节能与流畅模式，各至少两轮，交替顺序，避免机器温度与后台活动偏差。

CSV 包含进程 CPU（可超过 100%，以一个核心为 100%）、当前驻留内存、三屏交付帧率、帧合并数、GPU/回退帧数、yaw 与零偏。采样间隔约一秒。会话显示器变化时不跨会话计算帧率。

deliveryMS 为回调收到帧至主线程交付的平滑时间；sourceAgeMS 为帧时间戳至收到帧的大致时差。它们都不包含完整渲染、USB 输出和眼镜刷新链路，不能称为端到端延迟。静态桌面可能不持续提供完整帧，性能比较使用同一动态内容。

帧合并数上升意味着主线程来不及消费每帧，不能简单当作错误；应同时观察视觉卡顿、CPU、内存和帧率。GPU 路径若一直 fallback，需要记录系统、实际纹理设备和日志。内存验收建议运行 10 次启动/停止并观察驻留内存是否持续单向增长，而非要求缓存立即回到启动数值。

## 功耗、GPU 与端到端延迟

CPU 与内存由应用自动记录。GPU/整机功耗需在实机上结合 Activity Monitor 的能耗/GPU 观察，或按本机 `man powermetrics` 使用系统采样工具；powermetrics 需要管理员权限，不由应用自动提权。

真正的输入/转头到眼镜显示延迟需要高速摄像或等效测量。当前软件没有宣称得到该数值。验收时至少主观检查快速转头、文字滚动、窗口拖拽是否比兼容模式更卡顿。

## 阅读清晰度

保持三个 1920×1080 工作桌面。使用真实编辑器、终端、浏览器和文档，测试浅/深色主题以及不同字号；至少连续阅读 20 分钟。记录边缘文字、中心与侧屏可见范围、头部转动幅度和眼睛疲劳。

先调整屏幕大小、观看距离和间距，再改真实应用的字号。距离为场景单位，并非经过光学标定的真实米数。保存设置后重启确认还原。无需切换鼠标模式；任何跨屏输入回归均阻止把开发版标记为稳定。

## 姿态与漂移

1. 校准完成后回中，固定眼镜不动，采集 `--duration 600` 的 CSV，记录 yaw 变化、温度、零偏与 rejectedGaps。
2. 分别开/关“静止时缓慢修正零偏”，每种做同长度测试；更换选项后重新校准，避免继承前一轮偏置。
3. 左右各做约 30°、60° 转动并回到同一物理标记，比较回中误差；另测非常缓慢转头，检查静止修正是否影响有意运动。
4. 拔插和睡眠后确认重新校准，不能沿用断开前的积分时间跨度。

没有绝对航向传感器，持续 yaw 漂移不能保证消除；“回中”仍是必要操作。温度字段沿用协议参考，数值单位和实际可信范围需要在设备上确认。
